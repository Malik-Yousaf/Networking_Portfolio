Multi-site WAN with PPP and OSPF

Two city sites, Lahore and Sargodha, joined by a serial link. OSPF lets each site learn the other's LAN without static routes.

Connectivity: ready — OSPF should provide reachability between both site LANs.

What I configured

  • Point-to-point serial link on a /30 with PPP encapsulation on both ends.
  • Clock rate set on the Lahore side of the link, which is the DCE end.
  • OSPF process 1, area 0, advertising both site LANs and the WAN link.
  • One /24 LAN per site behind a switch, with static host addressing and gateways.

Three-router OSPF network

Lahore, Multan and Sargodha routers share two switched segments and exchange routes through OSPF area 0. Multan sits between the segments.

What I configured

  • OSPF process 1 in area 0 on all three routers, one network statement per connected segment.
  • Two switched segments, 192.168.10.0/24 and 192.168.20.0/24, each with its own hosts.
  • Multan has an interface in each segment and acts as the default gateway for both.
  • Routers on the same segment form OSPF neighbours over Ethernet.

Two-router network with RIPv2

Two LANs connected by a serial link, with RIP version 2 sharing routes between the routers.

What I configured

  • RIP version 2 with auto-summary turned off, so the /24 LANs are advertised exactly.
  • Serial link addressed as a /30 (10.0.0.0/30), clocking set on Router0.
  • Separate /24 LAN behind each router, with static host addressing.

Solved / documented

A three-zone Cisco ASA firewall lab: inside 192.168.1.0/24, outside 192.168.2.0/24 and DMZ 192.168.3.0/24. The uploaded Packet Tracer file contains ASA0, three switches and six end devices. The solution below completes the security design while keeping the original topology.

What was in the uploaded lab

  • ASA0 is a Cisco ASA 5505 running ASA 8.4(2).
  • Ethernet0/0 → VLAN 2 (outside), Ethernet0/1 → VLAN 1 (inside), Ethernet0/2 → VLAN 3 (DMZ).
  • Inside gateway: 192.168.1.1/24 with DHCP enabled from 192.168.1.5–192.168.1.36.
  • Outside gateway: 192.168.2.1/24; DMZ gateway: 192.168.3.1/24.
  • The uploaded file has three switches and six end devices, matching the three security zones.

Portfolio note: the uploaded Firewall System.pkt was inspected directly. Its stored ASA configuration contains the three VLAN interfaces and inside DHCP, but no configured ACL entries. The “completed” configuration above therefore adds the missing NAT object for an upstream/Internet scenario while preserving the ASA’s default trust-zone behavior. The interactive demo now shows an allowed Inside → Outside flow and a separate Outside → DMZ packet that stops at the firewall boundary and is marked BLOCKED.
